# 相机库与本地业务边界

基础流程先收口，再扩展云端与更多相机。本文件记录实施边界和待迁移项，不代表下表机型已经实测兼容。当前实现与证据另见[连接适配记录](CAMERA_BACKENDS.md)。

目标架构和交互不受旧内部API、历史布局或原型像素约束；可以按职责拆分和替换实现。照片、选片、项目、任务、历史与保存连接必须保留或经过可验证迁移，不能用卸载、清库完成重构。既有冻结包只作证据；本轮不改变支持的目标手机和系统范围。

## 分层

1. **传输和连接阶段**：Android管理USB授权、网络绑定、BLE发现与配对；iOS管理对应系统接口。发现、授权、协商、就绪、断开分别反馈，不能把获得IP或BLE已配对当作照片通道已连通
2. **协议适配器**：Sony PTP/IP、Fuji手机无线、Fuji AutoSave、Canon CCAPI、USB读卡分别实现实际操作。FTP接收与客户端是独立传输服务，不能伪装成完整卡内浏览
3. **协议族与差异配置**：共享握手、索引与文件读写实现；型号、固件仅覆盖有来源的差异。未知型号可在共享协议内安全探测，不通过改型号字符串开放能力
4. **领域业务**：图库、选片记录、项目和任务只消费媒体与能力契约，不按品牌调用协议指令。相机驱动不调用云上传
5. **存储与外部服务**：当前由Room、文件访问与预览缓存提供真实本地实现。后续云端通过Repository、Storage或Gateway接入现有业务和任务事件，不在每个驱动内重复上传逻辑

Android无平台依赖的目录、配置匹配、能力合并与业务规则优先Java；Compose、协程、USB/BLE/网络系统接口使用Kotlin。协议传输共用Go，iOS平台接口和界面使用Swift。是否复用现有实现按职责、维护成本和验证结果决定；不为统一语言机械重写，也不以旧签名阻挡必要重构。不提前引入云SDK或空同步框架。

## 已进入实际调用的模块

| 模块 | 生产调用与职责 |
|---|---|
| Java `CameraSupportRegistry` | 连接入口读取注册协议、端口和引导；`NativeCamera`连接前校验，连接后将能力与模式、型号/固件限制相交。协议族共用适配器；型号只提供差异数据，未知型号不冒充已实测 |
| Java `FujiGattProtocol` | Android蓝牙写入前校验允许的特征与载荷，限制在配对、客户端名和Wi-Fi启动；不允许快门、GPS、时间或备份恢复写入 |
| Java `FujiDiscoveryRules` | 先校验Fuji厂商ID与载荷，处理无名称广播、广告UUID、名称缓存、重复结果和关闭后的晚回调；生产扫描实际调用此规则 |
| Kotlin `FujiPhoneLink` | 蓝牙发现/配对、系统Wi-Fi确认、专用网络的请求与释放；不读取照片，不产生导入任务。回调绑定本次连接代次，取消后不发布旧结果 |
| `CameraPairingStore` / `SecureCameraPairingStore` | 配对凭据以协议和设备分域，复用已有本机加密存储；驱动不直接依赖设置或云账号。只有明确保存后写入token，忘记最后一份连接时清除其凭据，热点密码不存储 |
| Go `networkBackends` | 注册Canon、Fuji手机、AutoSave的工厂和默认端口；取消检查与会话发布集中在`Session`，不在每个分支重复实现。Sony继续通过同一PTP/IP实现处理所有Alpha型号 |
| Go `fuji_phone.go` / 共享Fuji媒体引擎 | 手机协议独立初始化与身份核对；仅复用封包、索引及安全发布。手机共享范围与AutoSave批次分开，预览不偷取整张RAF，原字节读取先协商尺寸再校验 |

连接信息、照片资源、文件、任务和选片继续通过现有领域对象传递；物理路径不作为设备或资源永久身份。Android与iOS消费同一Go媒体JSON边界，但本轮Java策略与Fuji蓝牙/Wi-Fi平台实现仅接入Android，iOS对应平台入口仍需独立实施与验收。

`CameraRuntime`的本地用例、文件访问和云调用仍需继续拆分；没有把它们标成已完成Repository迁移。本轮先用真实注册调用、共享USB、Fuji手机端点、缓存与导入证明边界可运行，再按功能移出其余职责。

Java/Kotlin的逐模块取舍与已替换算法见[语言边界](LANGUAGE_BOUNDARIES.md)。0.1.29将纯滑动选择范围移到Java，Compose触控与状态仍用Kotlin，没有翻译全部页面或Room实体。

## 交互与UI目标

- 连接按“选择方式→发现设备→系统/机身确认→核对身份→可用能力”推进。配对成功、获得IP和图库就绪分开反馈；记住设备后直接尝试重连，失败才回到对应设置
- 相机、图库、项目、传输使用同一导航和状态语言。手机/平板按实际窗口尺寸布局；缩窗、旋转不重新创建相机会话，不丢当前图片、选择或任务
- 取景以画面为中心，f/S/ISO/EV/WB/AF按真实能力开放；内部菜单中文。手机控件原位转正，专业工具按需展开，直方图保持小尺寸
- 选择是单一业务状态：普通浏览、大图、列表、网格和比较呈现一致。切图升级清晰度保留当前资源的像素，更换资源不能借用旧图；预览缓存始终区别于正式导入
- 主内容采用克制留白和模块化卡片；照片/取景优先，玻璃表面用于悬浮控制。尺寸、对比度、触控区域和动效服务操作，不靠模糊、低对比文字或大面积空白表现质感
- 任务反馈区分连接、读取、保存、预览和上传。错误提供可执行恢复动作；不会因云端离线阻断本地拍摄、浏览、导入和选片

## 共享与差异

| 协议族/服务 | 共享实现 | 差异与限制 |
|---|---|---|
| Sony Alpha PTP/IP | 现有Go连接、会话、媒体和控制实现 | A7C II、M4、M5等仅记录别名、固件限制与属性差异；以机身操作码和实时描述符决定功能，未验证的创意外观写入保持关闭 |
| USB PTP/MTP读卡 | Android通用Still Image设备枚举、对象读取和下载 | 不按厂商白名单排除Sony/Fuji；不把读卡模式等同于USB电脑遥控 |
| Fuji手机无线 | 独立手机握手与Android蓝牙/Wi-Fi交接代码，不能复用AutoSave身份或Sony初始化 | 已有独立端点与JNI业务验证；真实配对/手机会话/媒体范围仍待机身验收，未公布的RAF、取景或控制不标可用 |
| Fuji AutoSave | 现有实验后端与独立待传批次 | 与手机照片库分开，批次身份不能变成跨会话稳定设备身份 |
| Canon CCAPI | 现有HTTP端点协商和媒体实现 | 依实际公布端点、模式和能力开放，协议模拟不等于850D真机验收 |
| FTP | 现有接收服务、客户端、文件任务 | 设备支持FTP上传才可向App推送；不代表能从App枚举相机整张卡 |
| BLE | 发现、配对、快捷快门或Wi-Fi交接 | BLE配对成功不代表可传原片；各厂商遥控和交接协议分别实现 |

目录配置需有版本、来源和协议族继承。精确型号/固件限制优先于族默认；运行时最终能力取“适配器已实现、当前连接模式、机身公布、保护策略”的交集。未知、未实现、当前不可用、只读、可用分别表示，配置不能把只读或未知升级为可写。

保存的设备配置与协议差异配置分开。协议共享不合并设备凭据、信任、媒体缓存、选片或任务；连接代次变化后不发布旧请求结果。快门超时不自动重试。

## 媒体、任务与未来云端

- `Photo.id`、资源校验身份与选片记录关联继续沿用现有口径；设备资源身份必须包含来源与设备/会话范围，本地路径只代表物理位置
- JPEG和RAW是同一次拍摄下独立文件；逻辑原片、缩略图、临时JPEG预览、本地原片及未来远端对象分别记录
- 临时JPEG预览仍为缓存，不修改导入计数、文件保存状态或任务历史；选中导入时经资源及字节校验后可复用缓存
- 相机导入完成与未来上传/同步完成是不同状态；云端新增不能改写现有去重、取消、恢复或安全发布规则
- 相机凭据、SSH信任与未来云账号分域；未保存凭据仅在内存，保存时延续Keystore/Keychain保护；照片、GPS和配对秘密不默认同步
- 本地连接、取景、浏览、导入、选片、FTP不依赖云账号或互联网。Android/iOS共享领域契约，界面和硬件接口独立

领域契约按版本变更并同步调用与测试，不要求维持旧内部API。读取已有保存数据时，缺少协议的旧记录可明确迁移为Sony；明确的未知协议必须拒绝，不能静默套用Sony。新功能不得凭此迁移重写旧照片身份、下载计数或用户项目关系。

## 收口检查表

| 模块 | 当前需核对的风险 | 最小落地与验收 |
|---|---|---|
| 连接 | UI混合传输方式与协议名，配置切换和未知协议边界 | 实际注册/路由测试；错误协议不关闭既有会话；发现、授权、协商分阶段 |
| 取景与控制 | 布局重建、参数可写条件、快门超时和释放 | 同一会话旋转；能力限制；对焦实际执行；单张保护与失败释放 |
| 图库 | 大图切页请求升级短暂空白，浏览态隐藏已有勾选 | 保留同资源已解码画面；不同资源不串图；普通浏览、网格/列表、大图共享选择 |
| 索引与缓存 | 总数、分页排序、缓存与真实导入混淆 | 全量索引范围与末页；可见项缩略图；临时JPEG和RAW分离，缓存命中与取消字节检查 |
| 项目选片 | 筛选后大图范围、批次命名、删除及历史引用 | 当前业务范围一致；只删除指定记录；保留原片和其他项目关联 |
| 导入与FTP | 文件重名、取消后发布、历史与活动任务混清 | 原字节、无覆盖、代次校验；只清终态历史；后台生命周期独立 |
| 照片信息 | 预览EXIF被当作原片完整信息 | 标明来源；缺失保持缺失；GPS不自动上传 |
| 设置与发布 | 同版本不同包被当成同包、签名和平台状态混用 | 包散列对应源码/诊断组件；源码、构建、安装、实机分别记录 |

检查表中的待验项不会因文档存在而自动关闭。新功能还需检查：设备发现/保存/切换、取景与倒计时、筛选和JPEG/RAW选择、缓存复用、选片导出、任务恢复、凭据保护及跨端默认值。

## 阶段与验收边界

1. 当前本地缺陷修复和Fuji手机无线首条链路：先独立协议端点及生产路由测试，再构建独立候选包，最后验证真实设备。Fuji先身份、明确媒体范围、缩略图/JPEG预览、选定文件原字节与重连，再按证据接取景和参数；控制写入另验
2. 本地基础功能收口：手机、平板横竖屏与分屏分别验收；来源/选择/当前图片/任务不能因窗口变化丢失。用户报告Fuji USB基本接通只记为该路径的用户实测，不扩大为完整机型验收
3. 云端：路线已确认，具体功能、服务商、部署、收费和实际资料上传另行明确；复用领域与任务边界，不改相机驱动，不提前部署或上传用户资料
4. 更多机型：有共享协议的增量profile优先；不同协议新增adapter，分别补源码、协议、安装与机身证据。M4/M5、iPhone和平板无相应真机结果时保留待验
