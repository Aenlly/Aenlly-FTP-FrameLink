# FTP与界面完善记录

记录版本：FrameLink Android 0.1.1开发测试版。后续0.1.2界面规则与验收见[视觉记录](VISUAL_QA.md)，本页保留FTP功能对应关系

## 原版功能对应关系

| 原版功能 | 新版入口与处理 |
|---|---|
| FTP-Server启动/停止 | 首页“FTP 接收”，传输页也有同名入口 |
| 热点地址、账号与密码 | 自动列出手机实际局域网地址，可刷新，账号配置加密保存 |
| 自定义端口 | 接收表单直接设置，默认2121，范围1024至65535 |
| 上传保存目录 | “保存位置与压缩副本”通过系统文件夹授权选择，App内保留原文件 |
| 照片压缩、压缩目录、格式范围 | 独立JPEG副本，可配置尺寸上限、质量、格式和保存目录，保留原始字节 |
| 压缩图展示开关 | “压缩副本同步到系统相册”，原图和副本分别管理 |
| 配置记忆 | 接收配置和最近客户端账号保存在本机，凭证使用Android Keystore加密 |
| FTP-Client基础页面 | 完成服务器连接、目录浏览、搜索、上下级、文件夹创建、上传和多选下载 |
| 关于与署名 | 设置页和工程保留来源、许可证与原始源码，详见THIRD_PARTY_NOTICES.md |

原版接收页面的编码字段未实际传入服务器。新版明确使用服务器支持的UTF-8；客户端提供UTF-8、GBK和ISO-8859-1。原版缩放倍数改为可理解的图片尺寸上限与JPEG质量

## 文件与任务

- 收发使用二进制流和固定内存缓冲，原片不经过内存整图复制；当前256KiB输出缓冲与客户端下载校验的改动及本机对照见[FTP性能记录](FTP_PERFORMANCE.md)
- 接收完成落盘后才回复FTP成功；下载写入任务专属暂存文件，校验长度并落盘后再发布
- FTP客户端传输持久化到Room，支持取消和从头重试；不假设远端支持REST
- 每个传输使用独立连接，目录命令与文件数据流不会交错；收发和浏览不会占用UI线程
- 客户端上传先写任务专属暂存文件再改名，遇到同名目标拒绝覆盖；普通FTP服务器不能保证跨客户端并发下的原子不覆盖语义
- RAW、JPEG等照片加入图库；通用文件保留在传输任务，可打开、分享和通过系统另存
- 外部保存目录失去授权或压缩副本生成失败时，保留App原文件并提示重试
- 客户端的照片来源结合服务器、路径与文件内容摘要，重复导入相同照片不会重复建索引

## 界面

首页移除大幅宣传文案，相机状态卡收紧；六个常用入口采用两列Bento卡片，先展示选片下载、取景拍摄、FTP接收和FTP客户端。背景为灰白色，卡片为白色，主要间距16dp，强调色沿用摄影工具的柔和蓝色

底部导航、大图顶部信息和底部操作条使用玻璃材质。Android13及以上对实际背景图层进行GPU多点采样和圆角边缘折射，并叠加轻微高光；不模糊按钮文字。其他系统使用Haze背景模糊或半透明降级，不保证各系统与Apple原生渲染一致

卡片按压有轻微缩放和弹性恢复；正文和功能卡片保持清晰，照片大图维持深色沉浸环境。图库缩略图和文件名均可打开大图，复选框单独负责多选

## 验收范围

使用本项目独立Android模拟器和本机测试FTP服务器，不访问客户服务器。测试覆盖中文文件名、原始字节、错误密码、无效目录、上传同名保护、取消、下载失败后重试、JPEG/RAW/普通文件分流、压缩副本以及实际界面从连接到下载和查看大图

本机FTP测试不等于A7C II真机无线验收。FTPS代码遵循证书与主机名校验，生产FTPS服务器、旧Android玻璃降级、真实设备吞吐和耗电仍需独立验收
