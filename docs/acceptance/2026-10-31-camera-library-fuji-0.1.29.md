# 相机库、Fuji手机通道与Java规则：0.1.29候选1

本轮以相机库分层和Fuji手机无线首条链路推进。旧内部接口与布局不是重构约束，但用户照片、选择、任务、保存连接和冻结产物必须保留。本记录区分软件、安装和机身结果，不表示完整App或Fuji真机已验收。

## 实际代码

- Java协议/系列profile注册和模式、固件、能力限制已由连接入口与`NativeCamera`消费；无效协议/地址在切换会话前拒绝，USB只读模式不能因机型信息扩大为遥控
- Go以注册工厂处理Canon、Fuji手机、AutoSave的选择、默认端口和共同会话发布保护；Sony Alpha保持共用协议实现，没有按C2/M4/M5复制驱动
- Fuji手机独立初始化和共享媒体范围，支持软件验证的缩略图及指定文件原字节；临时JPEG不产生导入任务，正式JPEG导入可复用校验过的缓存，RAF独立处理
- Android蓝牙配对、系统Wi-Fi交接和局域网绑定已接入实验入口；只在允许的特征发送配对/客户端名/Wi-Fi启动，不写快门、GPS或时钟，不保存热点密码
- 配对存储通过独立接口注入，按协议与设备分域；明确保存后才持久化token，忘记最后一条相应连接时清除凭据
- Java发现规则先核对厂商与载荷，再处理无名称广播、广告UUID、名称后到、去重、缓存及晚回调；连接页呈现实时结果与扫描失败，不能凭系统bond列表判定BLE失败
- 多选范围提取为Java输入快照，手势和Compose状态仍用Kotlin；图片请求与缓存绑定资源身份，同路径同尺寸下更换资源也必须刷新

模块与后续迁移边界见[架构文档](../CAMERA_LIBRARY.md)，语言取舍见[语言边界](../LANGUAGE_BOUNDARIES.md)。`CameraRuntime`的其余用例/存储/云调用尚未全部拆分，iOS未接入Fuji蓝牙/Wi-Fi平台流程。

- 本轮先将红米和小米17覆盖安装到0.1.26并读回主包/诊断摘要；之后小米17安装0.1.28并读回匹配。它们是安装结果，不能替代真实连接验收
- 用户XApp截图报告X-T30 II、固件2.04、序列号不详；用户报告XApp自动识别，系统蓝牙列表没有记录。已授权走官方App连接界面对照，未读取其私有凭据
- Terra操作会话观察到XApp“已连接”、照片缩略图网格及取景页面；未按快门、调参或下载正式原片。网格来源和Wi-Fi切换没有独立核对，不能据此宣布光屿或完整相机卡流程通过
- 0.1.28扫描回调有结果但无Fuji候选；0.1.29修正已编译并通过生产规则反例，真实机身结构和完整配对仍待复核
- 0.1.29候选1交付操作会话时，ADB只见模拟器，两台真机未在线；候选覆盖安装及机身验证未执行。设备恢复后由同一操作会话继续，避免两边争用相机会话

本轮未触发刷机、删除卡内文件或格式化。光屿实现不发送时钟/GPS写入；XApp对照未更改时间、位置或自动传图设置，界面观察不能证明官方App没有执行原有自动同步。Mac曾只读尝试ImageCaptureCore DeviceInfo发现超时，不能因此声称机身未连接或推导当前固件。
