# iOS照片信息与JPEG临时原片缓存

2026-10-31，iOS0.1.9／build10。本轮仅软件检查、合成JPEG和隔离临时目录；没有操作实体设备、真实相机或客户照片。Android0.1.25、iOS0.1.7与0.1.8冻结产物保留。

## 实现

大图增加“查看原片”。仅请求配对的JPEG，保存到App私有的预览目录，不创建导入任务、不写入系统相册，也不改变JPEG／RAW的localPath与已导入数量。画面说明区分普通预览、临时JPEG原片、已导入原片，以及RAW已导入而JPEG仍未导入的情况。

缓存默认预算为2GiB，包含普通预览与临时JPEG原片。原片写入先校验接收长度、SHA256和JPEG类型，再发布完整缓存条目；相机照片ID包含设备身份、卡槽、资源编号和时间，缓存还匹配独立文件标识、名称、大小等字段，不只凭文件名复用。RAW与HEIF不复用JPEG缓存。正式导入时再次校验并复制到原片目录，之后才由原有导入流程更新状态。

较旧缓存自动淘汰，设置中可确认清除。清理会阻止迟到的预览写入重新填回；正式原片、项目、选片记录和传输历史不受影响。用户主动选择“删除App内原片与预览”时，仅删除所选照片对应的缓存并拒绝其迟到写入，其他照片缓存保留。启动时丢弃上一进程未完成的临时文件。预览目录排除系统备份。

文件信息新增ISO、快门、光圈、焦距、等效焦距、曝光补偿、机型、镜头、时间、像素尺寸、GPS、海拔和坐标基准。只读取已存在的本机非RAW原片、临时JPEG原片、RAW原片或已有预览，标明实际来源；不为了打开信息页自动下载原片，不用机身当前参数或手机位置补值。地图由用户主动打开，未知坐标基准不按WGS84定位。

当前大图只让活动页面持有高清图，原片解码长边上限8192像素，普通预览仍按较低上限处理，翻页与放大状态沿用原页面。**这是ImageIO缩略解码与单页内存控制，不是Android式区域瓦片解码，也没有提高相机的实时取景分辨率。** 大尺寸JPEG的内存与缩放体验仍需iPhone验收。

## 软件结果

| 检查 | 结果 |
|---|---|
| 核心回归 | `ios-0.1.9-core-release`退出0，30项测试零失败 |
| EXIF | 合成JPEG真实写入再读取ISO400、1/125秒、f/2.8、焦距、机型及南／西半球GPS；读取前后原始文件SHA256一致 |
| 缺失与错误字段 | 无EXIF、不完整或越界GPS、未知坐标基准、零曝光及非有限数值不显示为有效测量；不可解析文件有独立状态 |
| 缓存与导入 | 预览前后照片记录及导入状态不变；缓存字节校验、正式导入复制、同路径匹配恢复、不同内容的已有目标不覆盖 |
| 缓存边界 | 不同设备／时间资源隔离、RAW不复用、同长度数据损坏拒绝、预算淘汰、过大或错误接收拒绝、清理及单项删除后的迟到写入拒绝 |
| 界面编译 | `ios-0.1.9-ui-freeze2`退出0，模拟器App和UI测试工程编译通过；保留文件参数及清缓存后原片仍可读的UI用例 |
| 设备编译 | `ios-0.1.9-device-freeze2`退出0，iPhone arm64 App编译通过 |

回归中曾发现测试把两次JSON编码的原始字节当作照片不变依据，而JSON键顺序并不固定；已改为比较Photo值和原文件摘要。失败日志保留，最终通过记录独立归档。

完整成功日志位于`artifacts/FrameLink-0.1.9-ios-evidence/`。iOS0.1.9设备IPA仍未签名，需自签或开发团队签名后安装。打包脚本拒绝覆盖已有同版本IPA，清单记录源码提交及工作区状态。

## 尚未验收

- 本机CoreSimulator1174.9.2低于Xcode要求的1174.21.0，新增UI用例没有执行，不能把编译通过当成界面交互通过
- iPhone签名安装、真实相机JPEG读取、缓存命中导入、GPS跳地图及后台切换
- 真实20～30MB及更大照片的放大清晰度、低内存表现、缓存接近2GiB时的实际性能；合成小文件测试不代表此性能结果
- HEIF与各机型RAW的真实EXIF兼容、实时取景高清档位、更多品牌、iOS蓝牙与云端功能

元数据实现使用Apple系统[ImageIO EXIF字段](https://developer.apple.com/documentation/imageio/exif-dictionary-keys)与[关闭解码缓存的读取选项](https://developer.apple.com/documentation/imageio/kcgimagesourceshouldcache)。这些API说明不替代上述设备验收。
