# 筛选浏览范围与单图原片精度修正

2026-10-31，iOS0.1.18／build19源码候选。只修0.1.17图库详情接线与单图精度回归；原0.1.17源码、10份记录和旧APK／IPA保留。

## 筛选上下文

0.1.17网格使用筛选后的photos，详情却传入candidates全量来源，导致收藏A／C从A进入后“下一张”可能到未收藏B。这是本次窗口接入引入的回归。

- GalleryPhotoFilter同时服务实际网格与详情输入，保持来源原有顺序；不是另造一份测试过滤逻辑
- PhotoWorkspace明确保存browsingIDs，Gallery从当前photos建立上下文后才打开详情或进入对比。详情输入仅按这些ID解析，翻页、缩略条与“与下一张对比”都不能扩大到全量candidates
- 若正在查看的图因取消收藏／选择等不再命中，暂留当前这一张并显示提示，其余候选仍来自当前筛选；移到下一张后不再保留前一张。不再命中的非当前比较图会结束对比，不扩成全库
- 来源可用ID与浏览筛选ID分别保存，宽窄迁移只改几何，不清选择、关注点或筛选顺序。选片记录页也显式传入原记录顺序，避免从Set排序推导浏览顺序

## 原片精度

0.1.16已有本机原片／临时JPEG原片的单图上限为8192，0.1.17把它们一起固定降成4096，是精度回归。本轮恢复单个明确原片来源的原有路径，不用插值冒充已保留细节：

- 普通显示预览上限4096；实际解析到非RAW本机原片URL或已验证临时JPEG缓存URL时，单图上限8192；对比无论来源均每幅最多2048，缩略图限额不变
- PhotoDisplaySource依据实际resolved文件与照片文件路径／验证缓存路径判断，不按“已导入”标记或文件名猜测。只有RAW已导入而显示的是普通JPEG预览，不会误开原片精度；不会为了放大自动下载RAW
- 来源解析与本地解码任务分离。单图／对比切换只调整本地文件的解码限额，不重发原片读取或增加导入任务，资源身份与缩放归一化中心不变
- 大图继续走同一个串行ImageIO队列和取消令牌；切入对比清除当前高图并按2048排队，不启动双8192。已进入ImageIO的解码不能抢占，取消后结果丢弃；离开图片视图释放显示图，保留生产状态记录
- 文件信息如实说明普通／原片／对比限额。8192仍是显示上限，超过上限的源文件不是像素1:1；本轮未实现区域瓦片，也没有低内存设备或真实内存峰值结论

## 已执行软件验证

101项Core零失败，新增6项覆盖实际GalleryPhotoFilter、PhotoWorkspace、PhotoDisplaySource、PhotoDecodePolicy及PhotoDisplayDecoder生产入口：

1. A／C收藏、B不收藏，网格输入到详情、翻页、缩略条与比较均只在A／C，宽窄窗口输入不改范围
2. 当前A不再匹配时只暂留A，下一张到C后不再加入A或B
3. 已选／RAW／未导入使用同一生产筛选，保留原列表顺序；记录页浏览也不重排
4. 实际文件来源分类拒绝“RAW已导入”和相似文件名的假原片判断
5. 本机合成5000×3200高频条纹JPEG经实际ImageIO：普通预览4096，本机原片5000、临时JPEG原片5000；比较两幅2048，实际单队列并发峰值1。8192是限额，5000是本样本实际输出，不混称8192实拍结果
6. 精度切换复用同一URL、保留缩放关注点与选择，不新增任务；既有95项Core回归同时通过

新UI筛选／旋转／对比用例已准备，`gallery-window`专项扩为4项受影响UI。它们仅源码类型检查，未运行；Core范围检查与Mac ImageIO结果不能代替UIKit翻页／缩放、iPad分屏、实际原片观感或内存峰值验收。

独立归档为`artifacts/FrameLink-0.1.18-ios-evidence/receipt.json`。没有Go二进制框架重建、App链接、新IPA、Mac管理员重授权、未变协议重跑或Android整套回归。
