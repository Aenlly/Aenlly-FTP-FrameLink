# 富士接收页待连接退出边界

2026-10-31，iOS0.1.16／build17源码候选。只修正接收页许可、退出与尚未完成的连接发布，不改共享Go、相机协议、索引或文件发布逻辑。

## 确认的问题

0.1.15中，收到IMPORT并确认后，连接尚未完成时离开页面只停止接收监听，没有失效Session连接代次和导航回调。旧连接随后成功，仍可能发布cameraInfo并切回图库。另邀请阶段取消本地启用开关没有同步撤销邀请，接受入口也未复核当前许可。这是源码路径确认，不记为实机复现。

## 最小修正与App接线

- `FujiConnectionBoundary`是App实际使用的生产发布边界，持有页面身份、本次许可、连接尝试身份及导航回调
- 页面出现通过`openFujiPage`建立页面归属；退出通过`leaveFujiPage`失效尚未完成的连接。撤销Toggle同步调用`setFujiConsent(false)`，停止监听、清除邀请并取消待连接尝试。开关显示也读取AppModel的许可状态，后台停止后不留下视觉上的旧启用状态
- `acceptFujiInvitation`和`connectCamera`都复核同一页面许可；连接开始后由生产边界接管该次导航回调。取消回调绑定实际`AppModel.disconnect`，失效generation、清除回调并关闭Session
- `camera.connect`成功后，实际cameraInfo／属性／连接状态发布经过`fujiPage.publish`；失败经过`fujiPage.fail`。退出、停止、撤销或新尝试后，旧成功和旧错误都不能发布，也不能导航
- 成功时先清除“待连接”身份，再发布并调用导航。因此成功进入图库触发的onDisappear只关监听，不会断开有效批次。旧页面迟到的退出或Toggle事件不影响新页面
- 显式重新开始只认新连接尝试。普通Sony／Canon连接仍沿用原回调流程；实际Session关闭也会清除富士未完成的发布和导航身份

## 软件验证

84项Core测试零失败，新增6项覆盖：

1. 可控挂起连接后，退出／停止／撤销三种路径均调用一次取消，释放旧成功后不发布、不导航
2. 相同三种路径释放旧错误，不发布过时错误或导航
3. 成功发布后导航触发页面消失，不调用Session取消；同一成功不能重复发布
4. 显式新尝试拒绝旧成功和旧错误，只执行新发布及新导航
5. 未启用／已撤销许可拒绝接受，旧页面操作不取消新页面尝试
6. 实际Session关闭入口失效待发布回调，不递归重复调用取消

这些测试直接使用App调用的生产边界，并由可控挂起结果进入同一publish／fail入口；取消以回调调用计数验证，不宣称实际iPhone网络Session关闭已测。App接线由源码核对及真实Go生成头文件下的类型检查覆盖。保留默认关闭与启用后撤销的UI用例，但**UI尚未运行**，没有真实App挂起连接或设备实测结果。

最终Core日志和清洁提交的4步源码类型检查归档于`artifacts/FrameLink-0.1.16-ios-evidence/receipt.json`。共享Go与协议没有改动，本轮不重复0.1.15的12顶层／18子场景结果，相关证据继续使用原冻结记录。
