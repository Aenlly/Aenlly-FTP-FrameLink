# iOS图库、详情与双图窗口状态

2026-10-31，iOS0.1.17／build18源码候选。只调整图库／大图／双图及其共用缩略图组件，不改取景、相机连接、共享Go或任务发布业务。`docs/TABLET_GALLERY.md`继续是Android记录，不能作为本轮iOS通过证据。

## 生产接线

- GalleryView的实际GeometryReader测量内容窗口，按可用宽高和动态文字比例选择图库＋详情双栏或单栏覆盖。主导航结构不变；窄详情按需隐藏系统导航栏，导航显隐判定不依赖高度，避免显隐引起高度来回振荡
- 同一PhotoWorkspace由图库StateObject持有。宽窄切换不替换该对象或照片／传输会话；网格也保留在同一结构位置。SwiftUI scrollPosition绑定同一第一可见项ID，列数由网格自身宽度、目标单元格尺寸与字体缩放计算，手机列数不会直接放大到平板
- 当前照片ID、工具、文件信息开关及比较状态集中管理，不在详情onAppear重置当前图。原选片记录页的PhotoViewer调用保留兼容包装，初始图只在当前ID为空时建立
- 每张资源有独立PhotoViewportRecord，存放缩放倍率与归一化中心；按真实源／照片ID／槽／资源号／文件元数据隔离。正式文件localPath和缓存previewPath属于呈现修订，不冒充资源换代，因此同图后台落盘仍刷新来源并保留关注点；真实资源或来源改变不复用旧状态
- UIKit UIScrollView实际使用同一生产viewport.presentation计算缩放和偏移。尺寸变化时重算aspect-fit与边界夹紧，保留原归一化意图；程序化重排抑制代理回写，不把夹紧后的临时中心覆盖原关注点。用户缩放／平移写回每张图自己的记录，不靠ScrollView隐式状态跨窗口恢复
- 两张选择可从原选片条“对比”进入；详情也可明确选择“与下一张对比”。宽图像区域横排、窄区域纵排，使用AnyLayout保持子视图身份；两图分别缩放平移。对比中的缩略条只替换当前侧，工具显隐不改当前图；结束对比回到原当前照片，不改图库选择
- 窄窗选片条随隐藏的图库一起隐藏；宽窗留在网格栏底部，不叠加占用详情高度。详情主操作横向滚动且限制工具条高度，关闭与文件信息保持可达入口。大字／键盘及系统栏的实际触达仍需UI验收

## 图片读取与解码范围

普通大图仅通过原有previewURL入口解析显示来源；“查看原片”仍是唯一主动JPEG原片预览动作，RAW不会为了大图或比较自动下载。窗口、工具和缩放不属于呈现修订，不创建导入任务，也不会主动发出原片／RAW请求。

PhotoPreviewResolver是实际App使用的URL合并与取消边界，按资源＋呈现修订复用已存在的URL；后台正式文件落盘或缓存代次变化会重新解析。取消一个等待者不会丢掉另一个可见图的请求，旧代次结果不发布。已经进入原生层的不可取消预览命令不承诺被瞬间中止。

PhotoDisplayDecoder是App实际调用的ImageIO缩略解码器，源不全量缓存，显示图立即解码；大图独立串行队列最多1个ImageIO操作。单图长边最多4096，对比每幅最多2048，只建立当前1幅或比较2幅大图，不自动对两幅各解码8192。大图不按窗口每帧重解码，也没有区域瓦片、分区放大或源文件1:1像素保证。

缩略图按实际单元格尺寸×场景displayScale分64像素档取样，普通上限720；它有独立串行队列。大图和普通缩略图两个队列可以各运行1个，因此不能把“大图串行”写成全App只有1个解码。LazyVGrid／LazyHStack仍可能保留系统预取项，未宣称精确可见项内存上限。共用缩略图组件也用于既有页面，本轮没有扩大这些页面的UI验收结论。

按4字节RGBA计算，最坏正方形4096单图约64MiB，两个2048图共约32MiB；这是像素体积说明，不是实测峰值。旧图切换／原生ImageIO内部对象、缩略图、UIKit、导出图文单与缓存开销另算，未做低内存iPhone／iPad压力验收。
